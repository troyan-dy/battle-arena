## 2. Главные исправления (по убыванию эффекта)

### F1. Skeleton и brute — заглушка, которую анимирует трансформ всего спрайта (60 % врагов на экране)
- **WHAT:** `live/scene.js: drawEnemy`, fallback-ветка `if (!drawRig(e.type, …)) { … q = 1 + 0.06 * Math.sin(e.dist * 0.15) … }`. В `live/assets` нет `skeleton__*` и `brute__*` (в PLAN.md они в статусе «generating»). Кроп: `frames/qa/match.png` x 1060–1460, y 0–220, там белые «зайцы» с ушами (`study/critique/measure/placeholder_crop.png`, `match_half.png`).
- **WHY:** доля типов в живых сэмплах демо: skeleton 2836 (41 %), ghoul 2455 (35 %), brute 1354 (19 %), bat 353 (5 %). Больше половины орды не анимировано. Покрытие в qa проходит ложно, потому что в `SCENE.QA` стоит `walkers = ['hero','ghoul','skeleton','brute'].filter((n) => R[n])` и `actors = [...walkers, …]`: актёры без рига просто не попадают в список.
- **CHANGE:**
  1. Доделать `rigcut.py` для skeleton и brute. Код уже готов: `drawRig` универсален, `STRIDE.skeleton/brute` заданы, остаётся проверить `lift: 10` у brute.
  2. Пока ригов нет, не выпускать на экран тип без рига. В `sim.js: addEnemy` (или в ростере спавна): `if (typeof RIGS !== 'undefined' && !RIGS[type] && type !== 'bat') type = 'ghoul';`. Если sim не должен знать о RIGS, то же делается в scene через флаг `SIM.RIGGED = Object.keys(RIGS)`.
  3. В `SCENE.QA` строить `actors` из `SIM.TYPES` (все типы, которые спавнит sim), а не из `RIGS`. Тогда qa честно падает на coverage.

### F2. Каденс в 2–3 раза выше жанрового: нужен бег с фазой полёта и одинаковый шаг во всех направлениях
- **WHAT:** `live/sim.js`: `STRIDE = { hero: 54, ghoul: 34, … }`, `strideEff = st * (0.5 + 0.5·|gdx|)`. `live/scene.js: drawRig → foot()`: фаза опоры `u < 0.5`, коэффициент опоры D = 0,5. Это ходьба. `drop`: минимум таза в двойной опоре (тоже ходьба). Кроп: `frames/qa/cycle_hero_down.png`, кадры 0–11 (каждый 352 px шириной), весь цикл длится 0,135 с.
- **WHY:** cycleT: hero_right 0,27 с (3,7 пары/с), hero_down **0,135 с (7,4 пары/с, 8 кадров на цикл, 4 кадра на перенос ноги)**, ghoul_down 0,185 с (5,4). В демо у героя медиана 4,33 пары/с (8,7 шага/с), а 66 % времени он идёт по диагонали. Герой бежит со скоростью 200 px/s при H = 98, то есть 2,04 H/s, а это бег. При этом риг показывает шаг с D = 0,5 и максимумом таза в середине опоры (§15.1: у бега всё наоборот). Ограничение понятно: нарисованная нога длиной ~30 px не покрывает больше ~27 px опорного хода по x и ~13,5 px по y, поэтому шаг укоротили и подняли частоту. Правильный выход — фаза полёта: длина шага = ход в опоре / D.
- **CHANGE:**
  ```js
  // sim.js — один шаг-пара на STRIDE px в любом направлении (каденс задаёт тело, а не ракурс; камера сжимает глубину ~0.85)
  const STRIDE = { hero: 86, ghoul: 46, skeleton: 56, brute: 80, bat: 0 };
  const strideEff = (st, gdx) => st * (0.85 + 0.15 * Math.abs(gdx));
  // → герой 2,3 пары/с вбок, 2,7 по вертикали; ghoul 2,0 / 2,35
  ```
  ```js
  // scene.js drawRig: коэффициент опоры из того хода, который нарисованная нога может показать на экране; остаток цикла — полёт
  const ax = Math.abs(o.gdx || 0), ay = Math.abs(o.gdy || 0);
  const SW = (0.275 * ax + 0.15 * ay) * R.h;                 // максимальный ход опоры в px рига (≈ сегодняшние 77 / 38 px рига у героя)
  const D = Math.max(0.2, Math.min(0.5, SW / se));
  const foot = (side, u) => { …
    if (u < D) off = (D / 2 - u) * se;                       // опора: уезжает назад ровно со скоростью тела
    else { const q = (u - D) / (1 - D), e = q * q * (3 - 2 * q); off = (-D / 2 + e * D) * se; up = Math.sin(Math.PI * q) * lift; }
    … };
  // бег: таз ниже всего в середине опоры (u = D/2 и D/2 + 0.5), выше всего в полёте; один подскок на шаг
  let drop = run * 0.03 * R.h * (0.5 + 0.5 * Math.cos(4 * Math.PI * (uL - D / 2))) + (1 - run) * (…idle…) + …;
  ```
  Махи рук (`sw = fwd * se * 0.12`) при этом считать от угла, а не от `se` (см. F4), иначе с новым `se` они вырастут в 1,6 раза.

### F3. Ноги перекрещиваются («X») при движении вбок и на остановке
- **WHAT:** `drawRig → foot()`: `tx = hp[0] + (hipC[0] - hp[0]) * 0.5 * ax`, `nx = rest[0] + (tx - rest[0]) * (0.4 + 0.6 * ax) * run`. При движении вбок колеи стоп стягиваются к центру на половину ширины таза, а опорный ход ±13,5 px больше, чем остаток колеи. Кроп: `frames/qa/cycle_hero_right.png` кадр 0 (x 100–280, y 170–260 внутри кадра) и `study/critique/measure/hero_right_legs6.png` (кадры 0/2/4/6, ×5), `hero_stop.png` (кадры 4–8).
- **WHY:** hero_right, ankleL−ankleR по x: +18,2 / +11,7 / +2,2 / … / +2,2 / +11,7 при hipL−hipR = −17,7. Колени в кадре 0 тоже перекрещены (+4,6). Ghoul_right: +5,9 / +1,8 / +1,8. В `hero_stop` в кадре 6 обе стопы стоят на земле (y = −7) и перекрещены на 18 px. Обе стопы на одной линии земли, так что перекрест читается как узел, а не как «одна нога впереди другой». Проверка stance в qa смотрит только стойку, перекрест в цикле не проверяет ничего.
- **CHANGE:** колеи сужать только при движении по вертикали, при движении вбок держать нарисованную стойку. Плюс разнести стопы по глубине, чтобы при сближении ног одна была явно «за» другой:
  ```js
  const pull = 0.5 * (1 - ax);                                   // было 0.5 * ax — ровно наоборот
  const tx = hp[0] + (hipC[0] - hp[0]) * pull, nx = rest[0] + (tx - rest[0]) * run;
  const depth = side * ax * (o.gdx > 0 ? -1 : 1) * 3 / k;        // ведущая сторона чуть «за» (выше), другая ближе (ниже)
  return [nx + off * tdx * run, rest[1] + depth * run + off * tdy * run - up * run];
  ```
  и рисовать ноги в порядке по y стопы: дальняя (выше на экране) первой (§12 «Layer by depth in 3/4 view»). С нарисованными колеями ±20 px стопы при ходе ±13,5 не сходятся ближе 13 px, а максимальный разнос 40 px = 0,41 H (лимит 0,55 H).
  *Полное решение потребует арта:* 3/4-боковой и 3/4-задний вид героя и ghoul. Сейчас фронтальный риг при движении вбок идёт приставным шагом, а при движении вверх идёт спиной вперёд (§9). Если ракурсов не будет, это нужно занести в «known differences».

### F4. «Резиновая» рука с посохом и обломок корпуса в `hero__armL`
- **WHAT:** `drawRig`, цикл по рукам: `hd2 = sh2 + rot(ang)·L0·len + sw·(tdx, tdy)`, затем `drawPart(…, boneM(sh, hd, sh2, hd2))`. Кисть **сдвигается**, а `boneM` растягивает цельную руку по кости. Кроп: `study/critique/measure/hero_right_staffarm.png` (кадры 0/3/6/9, ×6, экранный бокс [902, 469, 129, 156], область x 60–118, y 40–105). Обломок виден в `hero_right_larm.png` (кадры 0/1/11, ×8, x 8–52, y 55–100).
- **WHY:** длина sh→hand у правой руки в `hero_right` меняется от 10,7 до 20,6 px при покое 15,1 px (0,71…1,36, отношение max/min = 1,93). Предплечье с кулаком заметно сплющивается и вытягивается. Левая рука: 1,13 при ходьбе вбок, 1,26 вниз (вниз это допустимое ракурсное сокращение). §15.1 «never scale a limb to reach», §15.2 «рука с оружием машет меньше». qa проверяет растяжение только у ног. Отдельно: в `art/gen/hero__armL.png` есть второй альфа-компонент на 203 px (bbox x 35–47, y 140–178 на холсте рига; в `live/assets/hero__armL.png` это x 35–47, y 67–105). Тёмная полоса от полы куртки едет вместе с рукой и висит в воздухе в кадрах 0, 1, 11 цикла `hero_right`.
- **CHANGE:**
  ```js
  // рука вращается вокруг плеча и не растягивается; рука с посохом машет на 40 %
  const amp = (s === 'R' && R.staff ? 0.4 : 1) * 0.22;              // рад
  const ang = ang0 - side * abd + tilt + fwd * amp * tdx;           // боковое движение: поворот в плоскости картинки
  const kf = 1 + 0.18 * fwd * tdy;                                  // к камере и от неё: проекционная длина (§15.2), ≤ ±18 %
  const hd2 = [sh2[0] + Math.cos(ang) * L0 * len, sh2[1] + Math.sin(ang) * L0 * len * kf];
  ```
  Стереть отдельный компонент в исходнике `art/gen/hero__armL.png` (x 35–47, y 140–178), затем перегнать `prep.py`. Попутно убрать соринку 9 px в `hero__body.png` (x 1–2, y 162–166) и 2 px в `ghoul__body.png`. По §12 разрез по перекрытию должен идти ступенькой.

### F5. Смерть: «осел и растаял» вместо «упал и лёг»
- **WHAT:** `drawRig`: `die = min(1, o.die/0.55)`, `tilt = lean + die*1.2*dieDir` (поворот вокруг `hipC`), `fL/fR ± die*6/k`, `drop += die*R.h*0.16`, `al = 1 − max(0, die−0.45)/0.55`. Кроп: `study/critique/measure/ghoul_death.png` (кадры 0…15 на +0 … +0,95 с, ×1,6).
- **WHY:** наклон корпуса растёт линейно: 2,9° → 12,1° → 25,9° → 42,8° → 58,8° → 68,8° на 0,033/0,1/0,2/0,333/0,467/0,55 с, то есть постоянные 125°/с без ускорения (нет веса). Голова в конце на высоте 24 px над землёй (1/3 H). Стопы скользят: левая с −4,3 до −23,3 px, правая с +2,6 до +23,1 px. В 0,55 с alpha уже 0, так что удара о землю и лежания нет. §13: «death (the whole rig falls and stays)».
- **CHANGE:** три фазы, пивот в точке земли (вся матрица `Mr`, а не `Mb` вокруг таза), стопы не скользят:
  ```js
  const dt = o.die >= 0 ? o.die : -1;
  const buckle = L.SS(0, 0.12, dt);                                // колени подламываются: таз −25 % H за 0,12 с
  const f = Math.max(0, Math.min(1, (dt - 0.08) / 0.30)), fall = f * f;      // падение с ускорением (как под гравитацией)
  const land = dt > 0.38 ? 0.10 * Math.exp(-(dt - 0.38) * 16) * Math.sin((dt - 0.38) * 38) : 0;   // один отскок
  const topple = (1.45 * fall + land) * (o.dieDir || 1);           // ≈ 83°: лежит на земле
  // Mr = M.of(M.t(gx, gy), M.r(topple), M.s(k*face, k), M.t(-g0[0], -g0[1])); drop += buckle * 0.25 * R.h; без fL/fR ± die
  const al = (o.alpha ?? 1) * (1 - L.SS(1.0, 1.35, dt));           // лежит 0,6 с, потом гаснет
  ```
  Пыль и кости (из PLAN) выпускать в момент `land`, а не в момент смерти. Тень гасить вместе с alpha.

### F6. Рывки таза на шагах, скольжение на остановке и на поворотах
- **WHAT:** `drawRig`: решатель досягаемости `d += Math.max(0, reach(...))` даёт излом (max с нулём) и V-образную просадку таза в двойной опоре. Стойка подмешивается через `run` сразу к обеим стопам (`nx = rest + … * run`, `off * run`). Направление `gdx/gdy` сглаживается в `gaitStep` (τ ≈ 83 мс) и отстаёт от скорости. Кроп: `study/critique/measure/hero_stop.png` (кадры 6–29), трасса демо `demo_trace.json` на t = 21,10 и 8,40 с.
- **WHY:** голова на 21,083/21,100/21,117 с: −88,3 → −84,4 → −87,3 px, Δ² = 6,8 px за 1/60 с (7 % H; это больше лимита pop для переходов в 6 %). Такие пики есть в 25–27 % кадров диагональной и вертикальной ходьбы. Метрики bob/limp их не видят: у qa 12 сэмплов на цикл, а на hero_down это 1 сэмпл на 11 мс. Остановка в qa: после того как тело встало, стопы ползут по земле на 25,6 px (ankleL 7,1 → −18,5) и 27 px (ankleR) за 0,37 с (кадры 7–29 по 1/60), почти не отрываясь от неё. В демо на остановках 3–7 px. На поворотах опорная стопа проскальзывает больше 1,5 px/кадр в 12 % опорных кадров (максимум 5,6 px на t = 4,63).
- **CHANGE:**
  1. Заменить `Math.max(0, x)` на гладкий softplus `(x + Math.hypot(x, 2 / k)) / 2`, а итоговый `drop` вести в sim пружиной (`S.hipDrop`, критическое демпфирование, ω ≈ 30). Тогда таз не ловит пики в 1 кадр.
  2. Остановка через последний шаг: когда скорость < 20 px/s, в `gaitStep` не гасить `gait` экспоненциально, а докрутить `gph` с последним каденсом до ближайшего касания (`gph mod 0.5 = D`). Во время этого переноса цель переносимой стопы плавно уходит из траектории шага в точку стойки, опорная стопа остаётся в своей мировой точке. Затем `gait = 0`. Это §15.4 «a stop settles into it foot by foot».
  3. Поворот: колеи и направление хода опорной стопы фиксировать на касании (запоминать `gdx/gdy` стопы в момент касания до её отрыва), а новое направление брать только для переносимой стопы.

### F7. Каст и укус ghoul: нет замаха, удержания и цели
- **WHAT:** `live/sim.js: castAmt`: `up = 1 − cd/0.12` (линейно), `down = 1 − (t − castT)/0.2` (линейно). `scene.js: drawEnemy`: `atk = max(0, 1 − |GT − atkT − 0.12|/0.14)` (треугольник 0,28 с). В `drawRig` при атаке `abd += atk·0.5`, `len = 1 − atk·0.2`. Кроп: `study/critique/measure/hero_cast.png` (демо 0,85–1,27 с, шаг 2/60) и `ghoul_attack.png`.
- **WHY:** каст: наклон посоха 9,4 → 26,8° за 7 кадров по прямой, пик 1 кадр (t = 1,000), линейный спад 12 кадров. Тело и левая рука не реагируют. Каст повторяется каждые 0,95 с, это главное «действие» героя на экране. Укус: обе руки **разводятся в стороны** на 0,5 рад и укорачиваются на 20 %. Получается «распахнул руки», то есть противоположность хватанию, и никак не учитывается направление на героя.
- **CHANGE:**
  ```js
  // sim.js — авторская кривая каста: замах вниз, рывок вверх с перелётом, удержание на выстреле, плавный возврат
  // (в sim.js `L` — длина петли демо, поэтому свой smoothstep)
  const ss = (a, b, x) => { const q = Math.max(0, Math.min(1, (x - a) / (b - a))); return q * q * (3 - 2 * q); };
  const castAmt = (S) => { const to = S.wp && S.wp.ice ? S.cd.ice : 9, since = S.t - S.castT;
    if (to < 0.16) { const q = 1 - to / 0.16; return q < 0.45 ? -0.2 * ss(0, 0.45, q) : -0.2 + 1.3 * ss(0.45, 0.85, q) - 0.1 * ss(0.85, 1, q); }
    if (since < 0.08) return 1;
    return 1 - ss(0.08, 0.36, since); };
  ```
  (`tip()` уже интерполирует, отрицательное значение даёт посох «вниз» на замахе). В сцене амплитуду поднять (`abd` 0.75 → 1.0, посох до ~35°), добавить отдачу корпуса на 1,5 px от выстрела и встречный мах левой руки (`abd += 0.15·cast`).
  Укус: руки вперёд к цели, не в стороны. Кисти сдвигаются по направлению на героя (10 px + 0.2 рад вперёд), корпус и голова делают выпад на 4 px к цели. Перед этим 0,08 с замаха назад (наклон −0.05), после выпада 0,06 с удержания. Направление передать как `o.tgx/o.tgy` из `drawEnemy` (SIM знает героя).

## 5. Мелкие замечания

- **Отбрасывание ghoul** (`sim.js`, цикл врагов): в `gaitStep(e, e.vx, e.vy, …)` не учитываются `kx/ky`, поэтому при ударе ледышкой (320 px/s, затухание `0.0005^t` → ~42 px) ноги шагают к герою, а тело едет назад. Пока |k| > 0,5·sp, гасить `gait` (`e.gait = max(0, e.gait − DT·12)`) и держать позу удара: так получится скольжение юзом, а не лунная походка.
- **Наклон героя при ударе** не зависит от направления: `lean = hitA·−0.08` при `face: 1`. Взять `fx` последнего события `hurt` и наклонять от атакующего: `lean += hitA·0.12·−sign(fx)`. Затухание сделать с одним отскоком (`1 − A·e^(−kt)·cos ωt`, §6), а не линейным.
- **Idle** (`breath`, `shift`): таз и голова ходят одним блоком на 3,1 px по y (диапазоны совпадают до сотых), это читается как приседания. Опустить амплитуду таза до ~1,2 px и добавить дыхательный сквош корпуса `M.s(1 − 0.008·breath, 1 + 0.015·breath)` вокруг таза. У ghoul дать собственный idle (подёргивание когтей, покачивание головы) вместо дыхания героя на той же частоте 2,3 рад/с.
- **Летучая мышь** (`drawBat`): ход крыла симметричный синус. Сделать быстрый взмах вниз (40 % цикла) и медленный вверх (60 %) со сложенным крылом (`sx` до 0,6 на подъёме и 1,0 на взмахе вниз). Добавить крен корпуса по `vx` (±0,15 рад). Сейчас корень крыла без щелей, частота 2,39 Гц для жанра нормальная.
- **Дальняя нога темнее** (`uFar`) всегда левая, потому что у героя `face = 1` при любом направлении. Для фронтального вида это произвольный выбор: либо брать дальнюю ногу по направлению хода (F3, depth lanes), либо не затемнять вовсе.
- **Стопа не перекатывается** (`footL/R` только переносится): в переносе нет подъёма носка, «пятка → носок» не показан. Во фронтальном виде достаточно сжать стопу по y до 0,8 в верхней точке переноса.
- **hero_stop в qa** длится всего 0,5 с (30 кадров по 1/60, sim идёт на 120 Гц) и начинается из перекрещенного положения ног. Стоит добавить второй вариант остановки, из фазы 0,25, и удлинить переход до 0,8 с, чтобы увидеть, как ноги садятся в стойку.
- **Каденс одинаков у всех врагов одной скорости**, фазы разные (rnd), это нормально. Но после F2 стоит добавить ±8 % к STRIDE на экземпляр (`e.ph`), чтобы толпа ghoul не «маршировала» на одной частоте.
- **Метки heel/toe** во фронтальном риге стоят по x (`rigcut --face left`): носок и пятка оказываются слева и справа, а не впереди и сзади. На картинку это не влияет, но slide/lift в qa меряются по условным точкам.
